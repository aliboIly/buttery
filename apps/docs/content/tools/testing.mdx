`expectButtery` from `@buttery/test` checks a page in Playwright against buttery's layout contract, at each viewport, theme and density you give it, and fails with every problem it finds and how to fix it. Use it in an app's end-to-end tests, so a layout that breaks at one size can't ship.

## A first test

```ts title="e2e/layout.spec.ts"
import { test } from "@playwright/test";
import { expectButtery, quickMatrix } from "@buttery/test";

test("the orders page is buttery", async ({ page }) => {
  await page.goto("/orders");
  await expectButtery(page, { ...quickMatrix, name: "orders" });
});
```

`quickMatrix` checks a 390px phone and a 1280px desktop, in light and dark. `fullMatrix` adds 768, 960, 1440 and 1728px and the compact density; buttery runs it before each release.

## Interactions

A page's open menus and toasts count too. Pass `interactions`, and each one drives the page; then every check runs on the state it leaves, and the stability check compares what moved.

```ts
await expectButtery(page, {
  ...quickMatrix,
  interactions: [
    {
      name: "open the export menu",
      run: async (current) => {
        await current.getByRole("button", { name: "Export" }).click();
      },
    },
  ],
});
```

Interactions run once, in order, at the first viewport, theme and density. An interaction that moves something on purpose, such as filtering a list's rows, lists the selectors of what moves in its `allowMove`. One whose state lasts, such as a form's errors, sets `acrossMatrix: true` to have that state checked at every viewport, theme and density.

## When it fails

A failed run prints each problem with the element, the rule, what it measured and a fix. The test's results also get `buttery-violations.json`, the problems as JSON, and an annotated screenshot for each viewport, theme and density where it found one.

[Reading a report](/guides/check-your-layout#reading-a-report) shows a report and what to do with it.
